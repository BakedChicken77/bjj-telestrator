# Native iPhone migration: N0 pilot

Status: implementation under validation, September 27, 2026. This is the first real-device interaction gate, not the completed native product.

## Baseline reconciliation

The migration branch starts at main `94c77e3` (1.1.1), integrates `codex/p1-completion` at `4bba6b2`, and preserves both parents in its GitHub history. PRs #8–#12 are a stacked Phase 1 series, not five independent patches. Their combined storage, schema-2 revision, recovery, asset registry, portable package, HDR, media-job, and export-plan code is integrated here. The old stack remains unmerged; it is superseded for this migration branch and should not also be merged piecemeal after this branch lands.

Recovered: main's session-fenced recording lifecycle, prepare/start distinction, suspension handling, phone recording dialog and expanded viewport; Phase 1's optimistic revisions, safe assets, recovery, import/export job semantics and fixtures. Recording start now flushes the revision-aware save queue rather than an independent save.

Deferred: full P2 feature roadmap, new schemas/persistence engines, desktop deletion, and public App Store submission. Existing CI gates remain mandatory. The native pilot intentionally retains the original editor for functions not ported yet.

## What this pilot can do

- Launch into a real SwiftUI review library and native navigation.
- Open a verified copy of an existing review in AVPlayer; scrub and seek using a filmstrip and slider.
- Rotate, pinch to zoom the view, pan with two fingers, and fit the video again.
- Draw arrows, lines, boxes, ellipses, freehand strokes, and text with native touch handling. Cues last up to five seconds from the playhead in this first version.
- Save each edit, undo/redo annotations, navigate to cues, and delete cues.
- Export a full-video MP4 through the existing native renderer, preserving existing audio tracks, then use the system share sheet.

Source audio plays in the native preview. Existing narration is preserved in the copied project and export, but preview narration mixing and new recording remain in the original editor. Cue selection/move/resize/retiming, native import, waveform/take controls, precise range export, accessibility alternatives, and performance tuning are later milestones.

## Data ownership

Original project JSON is read without invoking the migration-capable `load` method. Required source/proxy/narration assets are validated, space-checked, copied, and checksum-verified before the copy is atomically installed under `Application Support/BJJTelestrator/native-preview/projects`. Schema migration and edits occur only there. Original project IDs are preserved in the separate namespace. Reopening a preview resumes its saved copy; it does not overwrite edits with a fresh original.

Returning from the original editor pauses playback and flushes its autosave queue before dismissing it. Recording, active jobs, and import block this transition. The two interfaces never write the same folder.

This preview does not yet provide copy deletion or promotion back into the original library. Exported MP4s are the share route. Original media and project folders remain available to the original editor/package workflow.

## Validation and physical-device gate

Automated evidence: native XCTest coverage for original-byte preservation, copied-media integrity, schema migration, reopen, all six geometry types, normalized touch coordinates, and monotonically increasing revisions across undo/redo. Portrait/landscape screen attachments are generated by the simulator test. Existing native media, lifecycle, package, and recovery tests and all repository gates run alongside these tests.

Simulator checks do not establish physical touch quality, audio route behavior, performance, or final accessibility. Do not set `IOS_DEVICE_ACCEPTED=true` based on this pilot's CI.

On the TestFlight pilot, Steve should:

1. Open a copied real review and scrub to a position. Compare the feel with 1.1.1.
2. Switch to Draw; add an arrow and a freehand cue. Undo, redo, and navigate via Cues.
3. Rotate portrait/landscape, zoom, pan, fit, and scrub again. Look for accidental marks or stale overlays.
4. Close/reopen the copy; export/share a short review and confirm picture/cues and existing audio.
5. Open the original editor and confirm the original review is unchanged. Return using Done.
6. Report whether controls feel natural and reachable, and which interaction should change before the full port.

A positive interaction result unlocks the detailed N1–N4 native screens. N5 requires full native accessibility, recovery, audio-route, performance, and update-continuity acceptance. N6 removes desktop/web dependencies only after native parity and recovery are proven.

## Internal release and repeatable tester access

`release.yml` accepts owner-initiated pushes to `preview/native-iphone` as internal candidates, runs the existing full CI workflow, and uses the existing protected `ios-release` environment. Preview and tagged releases share one build-number counter, preventing collisions. Preview branch runs do not publish a public App Store release or GitHub release. PR #25 remains a draft until the pilot direction is accepted.

Both preview and normal release uploads now wait for Apple's exact app/version/build, reject failed or expired builds, verify the existing internal group's app and owner tester, assign the build if needed, and read back membership plus `IN_BETA_TESTING`. Receipts are uploaded as Actions artifacts. Apple's `hasAccessToAllBuilds` value is recorded; distribution does not depend on an undocumented setting mutation.

A processing timeout is a visible incomplete distribution, not an upload failure. The `testflight-upload.json` receipt identifies an already uploaded build. Retry `scripts/ci/distribute_testflight.py --version VERSION --build BUILD` with the protected environment credentials; do not re-upload the same version/build. API access or Apple processing failures may still require diagnosis. No workflow can guarantee Apple's availability.
