<a id="assessment"></a>

## The highest-return direction

Fresh Frame has a strong native foundation and a useful coaching workflow. Its biggest opportunity is to make existing capabilities feel connected: one understandable timeline, a video-first editor, and unmistakable narration states. The interface currently asks users to move among several different control surfaces to finish one task.

 

| Perspective | Assessment |
| --- | --- |
| Everyday user | Import is recognizable and the app stays focused on local video. The largest discovery gaps are finding saved work, selecting/editing an existing drawing, understanding pauses, and knowing how a finished MP4 differs from an editable backup. |
| Experienced reviewer | The tools are capable, but repeat work costs too many navigation and adjustment steps. Precise scrubbing, visible take playback, reusable styles, meaningful loops, and responsive mix edits offer the strongest efficiency gains. |
| iOS designer | Native components are already in place. The priority is hierarchy, state clarity, direct manipulation, adaptive layout, and fewer disconnected panels. The recording row provides a concrete example of a layout that needs redesign rather than smaller text. |

 

**Recommended product direction:** keep one persistent video canvas and time controller. Reveal drawing, narration, and export controls in context. Let a first-time user finish a simple review with very few decisions, while precise controls remain available when needed.

 

The recording, source, and existing test/plan documents support the findings below. Expected benefits are design judgments, not measured usability-study results. No app code, branch, pull request, release, or App Store setting was changed.

### Architecture that matters for UX

| Layer | Current implementation |
| --- | --- |
| App entry and navigation | SceneDelegate creates BJJNativeLibrary and presents BJJNativeHome through a SwiftUI hosting controller. Native review/editor screens are the primary iPhone experience. |
| Picture and interaction layer | SwiftUI controls surround a UIKit canvas using AVPlayerLayer, Core Image-rendered annotations, and gesture recognizers. Geometry is normalized to the actual video picture. |
| Editing and persistence | BJJNativeEditorSession owns the document and transient editor state. The local store validates and atomically saves JSON plus retained assets. Inspector drafts and completed canvas gestures have different, explicit commit boundaries. |
| Media preparation | Native Photos/Files import creates an owned media copy and a derived editing preview. Job services track cancellation, stages, failures, and bounded background execution. The current build configuration requests compatible Photos representation. |
| Narration and time | AVAudioRecorder creates retained takes. BJJReviewTimeline maps original-video time to finished-review time by inserting held frames; commentary can continue while the picture is frozen. |
| Preview and export | AVFoundation compositions map video, holds, and audio. Preview preparation builds a mixed PCM asset; export snapshots the saved revision and produces an ordinary H.264/AAC MP4 with annotations. |
| Recovery and portability | Backup packages, protected copies of earlier projects, recording recovery, immutable export inputs, checkpoints, and Recently Deleted are implemented to varying degrees in the services; not all are exposed by the native UI. |
| Legacy implementation | The repository also contains React/TypeScript and FastAPI/FFmpeg paths, plus a Capacitor bridge. Those are not the current primary native screen hierarchy. Desktop timeline features were not credited as existing iPhone UI. |

### Good foundations to preserve

- Preserve selected-item Photos access, local processing, retained originals, and the absence of an account requirement for editing.
- Keep the distinction between a finished MP4 and an editable review, while making it clearer to users.
- Preserve the existing timed-drawing geometry, atomic save transactions, and recoverable media ownership rules.
- Keep pause-aware narration: it is valuable functionality and a strong basis for a distinctive explanation workflow.
- Keep native sheets, system pickers, share sheets, semantic controls, and the optional tip model.
- Treat the supplied recording as visual evidence of real usage, while using the pinned implementation to resolve feature details.

 

The review does **not** relist paused-drawing visibility, basic pause-and-talk narration, inspector collapse, inspector Delete, automatic editor opening after import, or basic backup/trash support as missing features. They are present in the inspected implementation. Older planning documents and screenshots are not treated as the current UI.

## A simpler experience to aim for

**Home**

Select a video, continue the latest review, or open the full library. Preserve the branding and clear first-use state.

**Review and draw**

Keep the video and timeline stable. Selecting a drawing reveals its timing and style controls beside the picture.

**Narrate**

Use a focused dock with a timer, clear microphone state, Pause/Resume video, and Stop. Review takes with the video still visible.

**Share and keep**

Choose full review or a visible range, preview the result, save/share it, and retain access to completed exports and editable backups.

This is a proposed interaction direction, not a new tab hierarchy or implementation specification. New modes, panels, and features should earn their place through the tasks they simplify.

## Detailed recommendations

<a id="ux-01"></a>

### UX-01 — Give the editor one zoomable, precise timeline

**Category:** Timeline & playback · **Original rank:** 1 of 32 · **Effort:** Difficult · **Grouping:** Larger improvement

**Evidence confidence:** Code confirmed; current layout also visible in the recording

**Current experience**

The portrait editor has eight evenly spaced thumbnail buttons, a separate position slider, a horizontally scrolling strip of drawing cards, and a separate Cues sheet. Narration is managed elsewhere. The native main transport has no frame-step buttons, time-entry control, or zoomable time scale; the filmstrip and drawing strip disappear in landscape.

**Proposed experience**

Replace the disconnected time controls with one timeline beneath the video: thumbnails, a fixed playhead, and compact drawing/narration/paused-frame lanes. Start with a simple overview; expand only the selected lane. Let users drag to scrub, zoom the time scale with pinch or explicit +/− buttons, jump to the previous/next drawing or take, and tap the time to enter a position. Add fine-step buttons that accurately identify preview/output-frame stepping; true source-frame stepping needs a separate media implementation.

**User benefit**

Finding and revisiting the exact moment is central to every review. This makes long clips and dense annotations manageable and reduces repeated scrubbing.

**Priority rationale**

Highest overall value because it improves reviewing, drawing, narration alignment, looping, and range export. Deliver in stages rather than building a full multitrack editor at once.

**How to evaluate it**

Compare time and missed attempts when finding a specified grip change, revisiting a drawing, and aligning a short annotation in short and long clips.

### UX-02 — Create a focused, unmistakable recording interface

**Category:** Narration & audio · **Original rank:** 2 of 32 · **Effort:** Moderate · **Grouping:** Quick-start package

**Evidence confidence:** Code confirmed and visually observed

**Current experience**

Recording puts a long state label, an unlabeled progress-style audio meter, Pause/Resume video, and Stop into one horizontal row. Disabled playback, mode, and history controls remain visible. In the recording at 56 seconds, the state label wraps across several short lines. There is no elapsed recording timer in this UI, although the recording object exposes elapsed time.

**Proposed experience**

When capture starts, use a dedicated compact recording dock: a single-line Recording status and elapsed timer; a clearly labeled microphone meter; then two large actions, Pause video/Resume video and Stop recording. While paused, say 'Video frozen · microphone recording.' Hide irrelevant disabled tools. Display the active microphone before capture, offer a short optional countdown, and show the headphone guidance on first use or relevant route changes rather than forcing the same confirmation every take.

**User benefit**

Users can tell whether their voice is still being captured and stop or resume confidently. It fixes an observed polish problem in a core feature.

**Priority rationale**

Very high benefit with a smaller scope than timeline work; the layout/state-label portion is a strong first delivery.

**How to evaluate it**

Verify readable controls in portrait, landscape, and accessibility text sizes; confirm users distinguish pausing video from stopping the microphone.

Evidence: [S2](#source-S2) · [S8](#source-S8) · [V1](#source-V1)

Backlog issue: [#45](https://github.com/BakedChicken77/bjj-telestrator/issues/45) (added October 17).

### UX-03 — Keep the video and playback available while editing a drawing

**Category:** Drawing & editing · **Original rank:** 3 of 32 · **Effort:** Moderate · **Grouping:** Larger improvement

**Evidence confidence:** Code confirmed and visually corroborated

**Current experience**

Opening a drawing card or Cues entry switches to a properties layout with a scrollable Form and Save/Cancel. The normal filmstrip, transport, and tools are removed. The video remains visible, but the form contains its own seek slider and no play control. The existing collapsible inspector and staged draft are useful foundations.

**Proposed experience**

Use a contextual bottom inspector in portrait and a compact side inspector in landscape, with the same video and transport always available. Its first view should contain Timing, Style, Duplicate, and Delete; put numeric geometry and layer ordering behind More. Provide 'Preview this drawing' to play a small surrounding interval using the staged draft. Keep Apply/Cancel reachable even when the panel is collapsed. Preserve the existing atomic draft transaction.

**User benefit**

People can see the effect of an edit immediately and judge appearance and timing without repeatedly leaving and reopening properties.

**Priority rationale**

A frequent editing bottleneck with substantial existing infrastructure, so it ranks above most new features.

**How to evaluate it**

Have a user change a drawing's timing, replay it, resize it, and cancel the experiment without losing the saved version.

### UX-04 — Make take playback visible beside the video

**Category:** Narration & audio · **Original rank:** 4 of 32 · **Effort:** Moderate · **Grouping:** Larger improvement

**Evidence confidence:** Code confirmed; sheet occlusion is a design inference pending device walkthrough

**Current experience**

Narration opens a modal Form; selecting a take pushes another Form. 'Preview in video' starts the underlying player, but the take screen provides no video view. Playback is not explicitly bounded to the take's end. Takes are named only Take 1, Take 2, and so on.

**Proposed experience**

Present takes in a compact panel alongside the visible video. Selecting a take highlights its span and exposes Play take, Mute, volume, and timing. Play from just before the take to just after it, then stop or loop. Offer optional short take names, such as 'Grip explanation,' while retaining automatic numbering as the default.

**User benefit**

Users can check that words match the action and identify the right take without navigating away from the footage.

**Priority rationale**

High confidence usability gain built on existing playback and take metadata; waveform editing can come later.

**How to evaluate it**

Measure whether users can identify and correct a misaligned take without closing the narration panel.

### UX-05 — Make repeated audio and undo adjustments feel immediate

**Category:** Import & responsiveness · **Original rank:** 5 of 32 · **Effort:** Difficult · **Grouping:** Larger improvement

**Evidence confidence:** Preparation path is code confirmed; actual delay is unmeasured

**Current experience**

Each saved gain, mute, or take change can call prepareAudio. That routine builds a full-duration PCM preview and disables key interactions while preparing. Undo/redo also calls prepareAudio even when only a drawing changed. The work is streamed off the main actor, so this is not proof of a main-thread freeze, but the UI deliberately waits for it.

**Proposed experience**

Skip audio preparation for drawing-only history changes. Coalesce rapid volume adjustments and update a live mix where it can match exported sound. Cache a prepared mix by the relevant audio/timeline revision, invalidate only what changed, and preserve failure handling that prevents stale muted playback. Show small in-context updating feedback rather than repeatedly blocking the entire audio form.

**User benefit**

Volume balancing and undo become fluid, especially on longer reviews, and users can hear the result of an adjustment promptly.

**Priority rationale**

Potentially large benefit across frequent actions, discounted for media complexity and the need to measure the actual bottleneck before selecting an implementation.

**How to evaluate it**

Measure time from gain/mute/undo action to usable playback on short and long reviews; verify preview/export audio agreement and failure recovery.

Evidence: [S4](#source-S4) · [S9](#source-S9)

Backlog issue: [#48](https://github.com/BakedChicken77/bjj-telestrator/issues/48) (added October 17).

### UX-06 — Make every core workflow usable with larger text and assistive controls

**Category:** Accessibility · **Original rank:** 6 of 32 · **Effort:** Difficult · **Grouping:** Larger improvement

**Evidence confidence:** Existing support and remaining gaps confirmed in code; full assistive-use audit remains open

**Current experience**

Many controls already have labels and 44-point targets, the timing handles have VoiceOver adjustment actions, and numeric movement controls exist. However, custom drawing creation still depends on canvas gestures; pinch/two-finger pan have no equivalent visible zoom/pan controls. Several fixed horizontal rows and 150-point drawing cards risk poor reflow. Screenshot tests exist but do not establish end-to-end VoiceOver usability.

**Proposed experience**

Reflow dense rows vertically at accessibility sizes, keep actions reachable, and expose stateful names and values for custom controls. Provide Add drawing using a centered default shape, followed by accessible position/size controls; retain text-entry alternatives. Add explicit zoom controls and an accessible drawing/take list with context actions. Use labels, shapes, and selection marks alongside color, and announce meaningful state changes without reading every meter tick.

**User benefit**

Improves accuracy and readability for everyone while making the app usable for people who cannot precisely drag, pinch, or read small text.

**Priority rationale**

Cross-cutting product quality with broad impact. The whole workflow is difficult; obvious row reflow and label corrections can be delivered early.

**How to evaluate it**

Complete import, creation, timing, narration, undo, and export with VoiceOver and large text on a small iPhone; include Voice Control and reduced motion checks.

### UX-07 — Explain original-video time and finished-review time consistently

**Category:** Timeline & playback · **Original rank:** 7 of 32 · **Effort:** Moderate · **Grouping:** Quick-start package

**Evidence confidence:** Code confirmed; the recording demonstrates the two different durations

**Current experience**

The main slider and visible timestamp use outputTime, which includes narration pauses. Thumbnails, drawing timing, loop boundaries, and saved position use source-video time. Take display and export use the review/output timeline. The position slider's VoiceOver value currently reports source time even though its value is output time.

**Proposed experience**

Use finished-review time for the primary timeline and show inserted pauses as clearly labeled spans. When editing a drawing anchored to the original, label that time 'Original video' and show a linked finished-review position when needed. During a hold, show 'Paused at original 0:03.8.' Correct the VoiceOver value immediately, show elapsed/total review duration, and restore the precise review position inside a pause on reopen. Preserve source-time storage semantics.

**User benefit**

Prevents apparently contradictory timestamps, unexpected jumps, and uncertainty about what an exported range includes.

**Priority rationale**

High conceptual value and a dependency for the larger timeline, loop, and narration redesigns. Some wording and accessibility fixes are easy.

**How to evaluate it**

Use a 10-second source with a 5-second hold: users should understand the 15-second review and select the same moment from every relevant control.

### UX-08 — Add one-tap Continue review to the branded home

**Category:** Navigation & library · **Original rank:** 8 of 32 · **Effort:** Easy · **Grouping:** Quick win

**Evidence confidence:** Code confirmed and home screen visually observed

**Current experience**

Every launch presents the large logo, tagline, Select a video, Previous reviews, and Support Fresh Frame. Reopening a project requires opening Previous reviews and choosing a row. The session already saves playhead, speed, and loop preferences for that review.

**Proposed experience**

For returning users, add a compact 'Continue [review name]' card with its thumbnail and last edited time. Keep Select a video prominent and Previous reviews available for the full library. Preserve the large-logo first-use screen and adapt the returning layout without shrinking controls. Do not auto-open a review without a tap.

**User benefit**

Gets repeat users back to their work in one tap while preserving the identity and home-screen direction you already chose.

**Priority rationale**

### UX-29 — Use restrained feedback for important editing moments

**Category:** Visual design & feedback · **Original rank:** 29 of 32 · **Effort:** Easy · **Grouping:** Quick win

**Evidence confidence:** No explicit haptic calls found in the inspected editor controls

**Current experience**

The native controls show selection, disabled states, progress, and occasional text notices. The inspected editing implementation does not provide explicit selection/boundary haptics, and generic alerts carry many error cases.

**Proposed experience**

Use subtle haptics when a trim handle snaps to a boundary, a drawing is selected, or an action is successfully committed. Provide concise inline feedback for recoverable local issues; reserve alerts for decisions or failures that need attention. Respect accessibility preferences and avoid audible feedback—or unnecessary vibration—during microphone capture.

**User benefit**

Makes precise manipulation feel more responsive and reduces needless interruption.

**Priority rationale**

A low-cost finishing touch after behavior and layout are settled; feedback must confirm real state changes rather than mask delays.

**How to evaluate it**

Check feedback is neither repetitive nor required to understand state, and verify it does not interfere with recording.

### UX-30 — Allow starting a review from the iPhone share sheet

**Current experience**

Users start video imports inside Fresh Frame through Photos or Files. The app registers its editable .bjjproj document type, which serves a different purpose from receiving a movie shared from another app.

### UX-31 — Offer editable captions for narrated reviews

**Category:** Accessibility · **Original rank:** 31 of 32 · **Effort:** Difficult · **Grouping:** Optional expansion

**Evidence confidence:** No caption or transcription workflow in the inspected native app

**Current experience**

Narration is stored as audio takes; text annotations are manually positioned and timed. There is no generated transcript or caption track in the current native workflow.

**Proposed experience**

Offer opt-in captions after a take is saved. Let users correct the text and timing, preview readable caption styles, and choose whether captions appear in the exported video. Evaluate on-device transcription availability for supported languages/devices before selecting an architecture; do not silently upload recordings. **Priority rationale**

Meaningful recipient benefit, but accuracy, layout, timeline mapping, privacy, and export support make it a later feature rather than initial polish work.

**How to evaluate it**

Check corrections, technical vocabulary, speaker pauses, overlap with drawings, and caption timing after narration edits.

## How to choose and validate the next work

Before building the major redesign, use a small prototype and real review tasks with both first-time users and people who regularly annotate or narrate video. Keep a baseline of the current app; compare task completion, navigation steps, mistakes, and user confidence. The following are proposed evaluation tasks, not tests already performed.

 

| Task | Scenario | Useful evidence |
| --- | --- | --- |
| Find the moment | First-time and experienced users locate a specific action in a short clip and a longer review. | Time to correct position, overshoots, confusion about the active clock. |
| Edit a drawing | Create an arrow, move it, adjust its duration, replay, and undo. | Extra navigation, mode mistakes, ability to see the video and understand Save/Cancel. |
| Explain a frozen frame | Record, freeze, keep speaking, resume, stop, and replay. | Whether recording state and pause ownership are correctly understood; usable controls at large text sizes. |
| Correct narration | Identify a take, change its level, align it, delete/recover it. | Video visibility, action-to-playback delay, and avoidable rebuilds. |
| Share the right result | Export one narrated range and then reshare it after reopening. | Range accuracy, comprehension of output options, unnecessary rerendering. |
| Recover and access | Use denied-permission recovery, storage tools, backups, and VoiceOver workflows. | Task completion, preserved media, clear destructive scope, non-gesture alternatives. |

 

For media-related changes, preserve original assets, source-time annotation meaning, held-frame timing, preview/export agreement, atomic saves, backup compatibility, and existing reviews. Measure local and cloud-dependent import cases separately. A progress redesign does not establish a speed improvement, and simulator results do not establish microphone or physical-touch behavior.

 

After the review decisions, the most useful development brief would select a small group of related ranks, define before/after interactions, and state observable acceptance criteria. No development was started as part of this assessment.
